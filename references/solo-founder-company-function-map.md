# Solo-founder tech company function map

A real startup is not just "management and tech." It is a bundle of functions that happen to be staffed by one person at first.

## Core idea

At solo-founder stage, these are usually **functions**, not full departments. But the work still exists.

## The function map

| Function | What it owns | Real-world professional analog |
|---|---|---|
| Strategy / company design | vision, market choice, business model, sequencing, trade-offs | founder advisor, COO, strategy lead |
| Founder operating system | planning cadence, priorities, reviews, metrics, decisions | chief of staff, operating partner |
| Product | user research, problem selection, roadmap, pricing hypotheses, prioritization | product manager / head of product |
| Engineering architecture | stack choices, system design, trade-offs, platform direction | staff engineer / architect |
| DevOps / reliability | deployment, uptime, backups, observability, incidents, cost control | SRE / platform engineer |
| Security / privacy | threat thinking, data handling, vendor risk, policy, controls | security engineer / privacy operator |
| Finance | budgeting, runway, pricing math, gross margin, unit economics, reporting | startup finance lead / CFO / FP&A |
| Legal / compliance | entity docs, contracts, policies, statutory hygiene, regulatory triggers | startup lawyer + CA + CS |
| Payments | billing model, merchant of record vs gateway, settlement, fraud, chargebacks | payments operator / fintech operator |
| Growth / GTM | positioning, channels, experiments, acquisition loops, messaging | growth lead / marketer |
| Sales | qualification, demos, objections, pipeline, closing process | account executive / founder-led sales |
| Support / success | support workflows, issue triage, feedback loops, retention hygiene | support lead / customer success lead |
| Analytics / metrics | event design, KPI systems, dashboards, reporting cadence, instrumentation quality | analytics lead / growth analyst / product analyst |
| Pricing / monetization | pricing logic, packaging, plan design, usage limits, monetization experiments | pricing strategist / growth-finance operator |
| AI product ops | model quality, evals, routing, guardrails, cost/latency trade-offs, failure review | AI product operator / applied AI lead |
| Hiring / people ops | role design, hiring sequence, onboarding, accountability, people-risk hygiene | talent lead / people ops / startup operator |

## Deeper split: management

People often say "management" as one blob. For a startup, management usually breaks into:

1. **Strategy** — what business are we actually building?
2. **Operating system** — how do we review progress and make decisions?
3. **Finance** — is this economically working?
4. **Legal / compliance** — are we exposing ourselves to avoidable risk?
5. **Growth / GTM** — how do customers discover and understand us?
6. **Sales / support** — how do deals and customer trust actually move?
7. **Pricing / monetization** — how is value converted into revenue cleanly?
8. **Decision/risk management** — how do we prevent avoidable mistakes and drift?

## Deeper split: tech

People often say "tech" as one blob too. For a tech company, it usually breaks into:

1. **Product discovery** — what should be built and for whom?
2. **Architecture / platform** — how should the system be shaped?
3. **Implementation / delivery** — how does code get written safely and shipped?
4. **DevOps / reliability** — how does it stay running and observable?
5. **Security / privacy** — how do we reduce technical and data risk?
6. **Data / analytics** — how do we measure behavior and outcomes?
7. **AI / model operations** — if relevant, how are models evaluated, routed, monitored, and cost-controlled?
8. **Pricing instrumentation** — if usage/credits matter, how is monetization measured and controlled?

## Recommended solo-founder order

Do not try to master everything equally from day one. Build the function stack in this order:

### Wave 1 — must-have foundation
- strategy / company design
- founder operating system
- product discovery and prioritization
- engineering architecture and delivery
- legal / compliance basics
- finance basics

### Wave 2 — needed once shipping starts
- payments
- DevOps / reliability
- growth / GTM
- support / feedback ops

### Wave 3 — needed once traction begins
- sales process
- security / privacy maturity
- analytics / forecasting depth
- hiring / people systems
- deeper customer research program
- B2C growth loops if the product is audience-led

## Skill library recommendation

The best reusable skill library for a founder should map to these functions, not to one company. That means:

- keep skills general and profession-based
- keep repo/project docs case-specific
- create a new skill only when it will help across many companies or products

## Rule of thumb

If the content answers:

> "How would a strong professional in this function think and work?"

it belongs in a skill.

If the content answers:

> "What did we decide for this specific company or product?"

it belongs in repo docs or decision memos.
