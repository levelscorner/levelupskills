# Founder Operating System

## Overview

Use this skill to design the founder's decision rhythm: what gets reviewed, how priorities are set, which metrics matter, and how the founder prevents chaos from eating the company.

## Core Principle

A startup usually fails from **decision drift and attention fragmentation** before it fails from lack of ideas.

## Always cover

- weekly priorities
- decision log
- risk register
- KPI review
- product / engineering / revenue sync
- monthly strategy review
- stop-doing list

## Workflow

1. Identify the current stage and bottleneck.
2. Define the minimum operating cadence.
3. Pick 3-5 metrics that matter now.
4. Create a review rhythm: daily, weekly, monthly.
5. Define escalation triggers that force re-prioritization.

## Output format

Return:
1. current bottleneck diagnosis
2. weekly operating cadence
3. monthly review cadence
4. key metrics
5. decision / risk management rules

## Common pitfalls

- tracking too many metrics
- confusing activity with progress
- changing priorities too often
- no explicit risk review

## Verification checklist

- [ ] I designed a cadence the founder can actually sustain.
- [ ] I selected only stage-relevant metrics.
- [ ] I included re-prioritization triggers.
- [ ] I tied the system back to execution quality.
