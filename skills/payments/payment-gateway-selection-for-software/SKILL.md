# Payment Gateway Selection for Software

## Overview

Use this skill to choose payment infrastructure for software and digital-product companies.

## Core Principle

The right payment stack is the one that best balances **conversion, compliance burden, operational simplicity, cash flow, and future flexibility**.

## Key decision split

Always separate:
- merchant of record vs direct gateway
- domestic vs international needs
- one-time vs recurring billing
- software subscriptions vs marketplaces / regulated money movement

## Workflow

1. Identify product type, geography, and billing model.
2. Determine whether simplicity or control matters more right now.
3. Compare providers on onboarding, subscriptions, taxes, settlements, fraud, disputes, and developer ergonomics.
4. Flag legal/regulatory triggers.
5. Recommend now, later, and avoid options.

## Always evaluate

- subscriptions / recurring support
- payout model and reserves
- international acceptance
- tax/compliance burden
- fraud / chargeback handling
- implementation complexity
- vendor lock-in and migration pain

## Output format

Return:
1. current context assumptions
2. comparison table
3. best-fit option now
4. later-stage alternatives
5. due-diligence checklist

## Common pitfalls

- optimizing only for fees
- choosing control before operational readiness exists
- ignoring tax/compliance ownership
- treating all software payment businesses as identical
