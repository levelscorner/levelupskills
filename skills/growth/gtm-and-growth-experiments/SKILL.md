# GTM and Growth Experiments

## Overview
Use this skill to design go-to-market learning systems: what message to test, where to test it, how to interpret results, and how to avoid random channel flailing. The goal is not endless experimentation. The goal is disciplined signal.

## When to Use
Use this skill when the main problem is **how to learn what GTM motion works**.

Typical triggers:
- no clear acquisition channel
- too many channel ideas and no prioritization
- unclear messaging-market fit
- early GTM motion is noisy and anecdotal
- the team needs experiments rather than large commitments
- growth decisions are being made without enough evidence

Do **not** use this as the main skill when:
- the task is strategic brand/message architecture → use `brand-positioning-and-messaging`
- the task is direct founder-led selling → use `founder-sales-for-b2b`
- the task is product-priority logic rather than GTM learning → use `product-discovery-and-prioritization`

## Core Principle
Early GTM wins by learning quickly which audience-message-channel combinations create believable traction, then concentrating effort there.

## Always cover
- ICP / target user
- message hypothesis
- channel hypothesis
- experiment design
- success metrics
- stop / continue / double-down logic

## Workflow
1. Clarify product, ICP, and buying or adoption context.
2. Identify the biggest GTM uncertainty.
3. Design the smallest useful experiment to reduce that uncertainty.
4. Define what would count as signal, noise, or false positive.
5. Recommend how to sequence the next learning steps.

## Output format
Return:
1. GTM uncertainty diagnosis
2. recommended experiment stack
3. channel and message priorities
4. measurement logic
5. next learning decisions

## Common pitfalls
1. **Running many experiments with no shared learning question.** Activity can mask ignorance.
2. **Testing channels before clarifying audience or message.** Distribution cannot rescue mushy positioning.
3. **Reading weak sample sizes as proof.** Early signals need humility.
4. **Confusing attention with conversion quality.** Traffic is not traction.
5. **Scaling before repeatability.** That turns experiments into expensive habits.

## Verification checklist
- [ ] I identified the biggest GTM uncertainty.
- [ ] I proposed experiments tied to learning, not just activity.
- [ ] I defined success and false-positive signals.
- [ ] I recommended sequencing rather than a random experiment pile.

## Examples
### Example: early SaaS GTM
Return:
1. The team does not yet know whether the right wedge is founder pain or team workflow pain.
2. Test two message hypotheses in one or two channels, not six.
3. Use conversion quality and follow-up interest, not clicks alone, as signal.
4. Pause large channel spend until one motion shows believable repeatability.
5. Feed results back into positioning and product conversations.

### Example: noisy acquisition
Return:
1. Current problem is lack of experiment discipline, not lack of ideas.
2. Collapse work into a smaller set of hypothesis-led tests.
3. Define stop rules before launch.
4. Track downstream quality, not just lead count.
5. Double down only where evidence survives follow-up.
