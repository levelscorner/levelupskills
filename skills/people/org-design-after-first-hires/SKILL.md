# Org Design After First Hires

## Overview
Use this skill to help a startup shape team structure once work can no longer sit cleanly inside one founder's head. The goal is to reduce coordination pain and ownership confusion without creating premature bureaucracy.

## When to Use
Use this skill when the main problem is **team structure**.

Typical triggers:
- founder bottlenecks caused by too many direct ownership threads
- unclear responsibilities after the first hires
- reporting-line or management-layer decisions
- repeated handoff confusion across product, engineering, GTM, or ops
- deciding what remains founder-led vs delegated

Do **not** use this as the main skill when:
- the question is mainly who to hire next → use `hiring-and-people-ops-for-startups`
- the question is overall company function map → use `startup-company-design`
- the question is operating cadence and review rhythms → use `founder-operating-system`

## Core Principle
Org design should reduce coordination pain and ownership confusion without creating premature bureaucracy.

## Always cover
- current bottlenecks
- roles and ownership
- reporting / management logic
- coordination costs
- delegation boundaries
- likely next org inflection point

## Workflow
1. Clarify current team size, founder bottlenecks, and work streams.
2. Diagnose whether the problem is role ambiguity, span overload, handoff friction, or missing management systems.
3. Recommend a structure proportionate to stage.
4. Define ownership boundaries, reporting logic, and decision rights.
5. Highlight what should remain founder-led versus delegated.

## Output format
Return:
1. org-stage diagnosis
2. recommended structure
3. role / ownership changes
4. bottlenecks and risks
5. next scaling trigger

## Common pitfalls
1. **Adding management layers before management work exists.** Structure should solve a real coordination problem.
2. **Using titles to hide unclear ownership.** Naming is not design.
3. **Keeping every decision founder-owned too long.** That caps team leverage.
4. **Copying big-company org charts too early.** Early-stage teams need simpler structures.
5. **Ignoring the next inflection point.** Good org design should survive the next hiring wave, not just this week.

## Verification checklist
- [ ] I identified the actual coordination bottleneck.
- [ ] I matched the structure to stage rather than prestige.
- [ ] I defined ownership and delegation boundaries clearly.
- [ ] I named the next scaling trigger that would justify another org change.

## Examples
### Example: 6-person startup
Return:
1. Bottleneck is founder context overload, not missing middle management.
2. Create clearer functional ownership before adding managers.
3. Keep product and engineering tightly linked, but assign one clear owner per workflow.
4. Delegate routine decisions with explicit boundaries.
5. Revisit management layers only when direct-report load and cross-team coordination justify it.
